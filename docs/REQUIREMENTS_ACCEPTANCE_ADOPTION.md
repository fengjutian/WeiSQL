# V1 需求与验收基线吸收说明

> 状态：已纳入项目文档治理参考  
> 记录日期：2026-11-02  
> 参考文件：`REQUIREMENTS_V1.md`、`ACCEPTANCE_MATRIX_V1.md` 及其 `README.md`

## 1. 定位

外部《WeiSQL AI V1 完整需求规格说明书与验收标准》及验收追踪矩阵，作为 WeiSQL 的需求治理、证据管理和发布验收参考基线。

这些材料定义的是验收要求，不天然构成功能已经实现、已经验证或可以正式发布的证据。仓库中已有的更新版规范、ADR、实现、自动化测试和可复现基准结果继续作为当前工程事实来源；发生冲突时，应核对文档版本与证据，并通过 ADR 或规范修订明确结论，不以旧草案静默覆盖新事实。

## 2. 已吸收原则

1. 每项需求应有稳定 ID，并关联实现位置、测试用例、当前状态、验收证据及相关决策。
2. 没有可复现证据的能力不得标记为 `verified` 或 `released`。
3. 代码、设计稿、TODO、模拟结果或未执行的测试命令，不构成验收通过证据。
4. SQL 与资源访问采用 fail-closed 安全边界；只读保证不能仅依赖字符串前缀判断。
5. Manifest、数据分片、向量、ID 映射和索引必须绑定一致的数据集版本，禁止静默混用。
6. 浏览器、Node.js 与 CDN/静态托管路径分别验证；单元测试不能替代真实环境集成测试。
7. 性能与召回结论必须附带硬件、运行时、数据规模、维度、分布、参数、重复次数和原始结果；不得用估算代替实测。
8. 稳定能力、实验能力、已知限制与延后事项必须清晰区分，不得扩大宣传口径。
9. Builder 输出必须能由 SDK 重新打开并完成格式、摘要、版本和 ID 映射校验。
10. 发布前必须检查许可证、NOTICE、构建产物、干净安装、示例和 smoke test。

## 3. 与当前仓库的关系

参考材料形成时，`.wsql`、全文/混合检索、签名和部分 ANN 能力仍被列为可选或待验证；当前仓库已经存在相关实现、测试或实测记录。因此：

- 产品与工程现状以 `docs/PROJECT_STATUS.md`、`README.md`、当前专项规范及 `docs/DECISION_LOG.md` 为准；
- 验收状态只能由当前可复现证据支持，不能仅依据状态报告中的概述；
- 旧矩阵中的“待核验”不是对当前实现的否定，而是需要重新建立需求到现有证据的映射；
- 新能力若超出原 V1 范围，仍须遵守相同的安全、兼容性、证据和发布纪律。

## 4. 后续采用方式

后续需求评审、实现审查和发布判断按以下顺序执行：

1. 确认需求 ID、级别、边界和明确不做事项；
2. 映射当前实现、测试、文档和 ADR；
3. 运行或复核可复现证据，不以历史结论代替本次验证；
4. 将未验证项保持为真实状态，并记录缺口与阻塞原因；
5. 对冲突或范围变化形成显式决策记录；
6. 发布时逐项关闭阻塞门槛，并公开剩余限制。

## 5. 发布判断底线

以下情况不得宣称能力已经稳定或适合生产使用：

- 只读安全边界没有攻击用例证明；
- 资源完整性、路径或版本错配不能可靠失败；
- 浏览器或 Node.js 的声明路径没有真实环境验证；
- 向量与业务记录的 ID 映射无法证明正确；
- Builder 产物不能被 SDK 完整校验和读取；
- 性能数字无法复现，或没有披露数据分布与运行环境；
- 许可证、发布产物或干净安装检查尚未完成；
- 把实验性 ANN、容器格式或其他未验证能力写成稳定承诺。

本说明用于把外部 V1 材料的治理思想纳入当前项目，不替代原始需求全文，也不单独构成任何验收项目通过的证据。
