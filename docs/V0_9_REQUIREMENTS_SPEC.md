## 一、产品目标与边界

WeiSQL AI 不是简单地把 SQLite 换一个名字，也不是要求用户部署一个独立数据库服务器。它的核心是将结构化数据、向量数据、全文检索能力和查询接口组合成可分发的数据包，并在不同运行环境中使用统一的 TypeScript SDK。

### V1 必须达到的目标

1. 静态部署：可以将数据包随静态网站发布到支持相应文件访问能力的 CDN 或 Netlify。
2. 统一 API：浏览器和 Node.js 使用尽可能一致的公开查询接口。
3. 只读运行：不依赖独立数据库服务器，不在 V1 中承诺写事务或多用户同步。
4. 混合检索：支持 SQL 筛选、向量相似度检索，并为全文检索及混合排序建立扩展接口。
5. 按需加载：大型数据集不应默认整体读入内存。
6. 可验证性：数据包、资源文件、索引和版本之间能够进行一致性检查。

### V1 暂不承诺

| 能力                | V1 处理方式              |
| ----------------- | -------------------- |
| 多用户并发写入           | 不支持                  |
| 完整事务与 WAL         | 不支持                  |
| 分布式数据库集群          | 不支持                  |
| 任意 SQL 方言兼容       | 明确支持的 SQL 子集及引擎能力    |
| 百万级向量性能承诺         | 先基准测试，再确定支持范围        |
| 任意 CDN 自动支持 Range | 必须验证服务器行为            |
| AI 模型推理           | 由调用方提供，WeiSQL 负责数据检索 |

## 四、核心业务规则

### 4.1 数据包规则

- 所有资源使用规范化的相对 POSIX 路径。
- 拒绝绝对路径、`..` 路径段、空路径段、反斜杠、URL scheme、NUL 字符及其他危险路径形式。
- 同一 V1 数据包中不允许不同资源声明重复使用同一路径，除非未来专门定义共享资源机制。
- Manifest 的 `formatVersion` 表示格式兼容版本；数据集的 release/version 单独管理。
- SHA-256 用于校验实际文件与声明内容是否一致，不等于验证发布者身份。
- ID 映射文件的偏移表采用 `count + 1` 个边界偏移，首项为 0，末项等于 JSONL 文件字节数。
- 空向量集合合法，数量为 0 时 Top-K 结果必须为 `[]`。

### 4.2 向量规则

| 项目     | 规则                                         |
| ------ | ------------------------------------------ |
| 存储格式   | Float32 little-endian，按行排列                 |
| 向量长度   | 必须等于集合声明的 dimension                        |
| 元素合法性  | 不允许 NaN 或 Infinity                         |
| Cosine | 距离为 \\(1-\text{cosine similarity}\\)，零向量报错 |
| L2     | 使用欧氏距离                                     |
| IP     | 使用负内积，使所有指标都按升序取最近结果                       |
| Top-K  | 必须为正整数                                     |
| 同距离结果  | 按行号升序，保证稳定排序                               |
| 数据块    | 必须连续、无重叠、无缺失，并覆盖完整集合                       |
| ANN 结果 | 必须明确标记为近似结果，不得冒称全局精确 Top-K                 |

### 4.3 SQL 与向量过滤规则

首版混合查询采用 TypeScript 编排 SQL 与向量检索，不直接修改 DuckDB 内部查询计划。

- `exact-filter-first`：先确定符合 SQL 条件的候选集合，再进行精确向量比较，可保证过滤集合内的全局 Top-K。
- `vector-first`：先取得有限数量的向量候选，再进行 SQL 过滤；可能不足 K 条，不能保证过滤集合内的全局 Top-K。
- 过滤条件使用结构化表达式，不直接拼接任意 SQL 字符串。
- 字段名必须对照表结构校验；值使用参数绑定。
- 不允许在公开 API 中使用 DuckDB 或 USearch 专有类型。

## 五、非功能需求与验收标准

性能目标需要先测量再冻结，尤其不能把硬件、数据维度和内存容量不同的测试结果混为一谈。

| 测试项        | 验收要求                                     |
| ---------- | ---------------------------------------- |
| 正确性        | 精确搜索结果与独立暴力排序基准一致                        |
| Top-K      | 包括距离相同、K 大于数据量、空集合等边界                    |
| 数据完整性      | 能发现文件缺失、大小不符、哈希错误、偏移表损坏                  |
| 分块读取       | 能发现缺失块、重复块、乱序块和截断数据                      |
| 取消操作       | 收到取消信号后按约定终止，不将取消误报为查询成功                 |
| 资源关闭       | 关闭后拒绝新读取，并定义在途任务的处理方式                    |
| 浏览器兼容      | 验证 WASM、CORS、HTTP Range、缓存及内存上限          |
| Node.js 安全 | 校验真实路径边界，并覆盖符号链接与文件替换风险                  |
| 性能         | 分别测量 100K、500K、1M 向量的 P50/P95 延迟、内存和索引大小 |
| 近似召回       | ANN 与精确基线对比 Recall\@K                    |
| 发布原子性      | 构建失败时不发布半成品                              |
| 版本兼容       | 旧版 Manifest 的读取或拒绝行为有明确规则                |

建议基准测试使用可复现数据、固定随机种子，并分别报告向量维度、距离指标、硬件、浏览器版本、数据格式、缓存状态及是否使用 ANN。
