## 一句话

<Module>

WeiSQL 的核心设计只有一句话：**把“数据库服务”换成“可版本化的静态数据包 + 一层只读 Runtime”**。理解这一点，后面的 Adapter、缓存、完整性校验都是它的推论。

<Callout title="两个方向都是单向依赖">
  上层只依赖接口，不依赖具体引擎；Adapter 通过 `open({ sqlAdapter, vectorAdapter })`
  注入，能力通过 `capabilities()` 如实上报。SDK 本身没有 DuckDB、USearch 的运行时依赖。
</Callout>

</Module>

## 2. 设计原则

<Module>

<CardGrid columns={2}>
  <DocCard title="显式失败" index="01">

没有 Reader 返回 `INDEX_NOT_FOUND`，没有 SQL Adapter 返回 `SQL_UNSUPPORTED`，不返回空数组假装成功。

</DocCard>
  <DocCard title="引擎可替换" index="02">

Adapter 注入，SDK 零引擎依赖；浏览器与 Node 可以选不同实现，能力差异用 `capabilities()` 暴露。

</DocCard>
  <DocCard title="精确优先" index="03">

ANN 必须自报 `exact: false`；后过滤必须自报 `postFiltered: true`。

</DocCard>
  <DocCard title="测量先于承诺" index="04">

基准装置是测量设备，不是性能承诺；召回数字必须连同数据分布一起报告。

</DocCard>
  <DocCard title="发布不可变" index="05">

缓存按发布版本身份隔离；换版本即失效，避免新旧资源混用。

</DocCard>
  <DocCard title="只读是产品边界" index="06">

没有写入、事务与锁；需要这些能力时应换方案，而不是等排期。

</DocCard>
</CardGrid>

</Module>
