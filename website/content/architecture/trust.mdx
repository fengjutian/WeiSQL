## 1. 信任边界

<Module>

Manifest 和所有远程资源都按**不可信输入**处理：

<CardGrid columns={2}>
  <DocCard title="路径" index="01">

规范化后再 I/O；拒绝绝对路径、`..`、反斜杠、URL scheme 与重复规范路径。

</DocCard>
  <DocCard title="传输" index="02">

HTTP 只接受 `206` 与匹配的 `Content-Range`；短读、超长、取消都不进入缓存。

</DocCard>
  <DocCard title="内容" index="03">

L3 用声明尺寸与 SHA-256 检测损坏；签名用于发布者身份，二者不是一回事。

</DocCard>
  <DocCard title="SQL" index="04">

只读语句分类、参数绑定、单语句；`memory` 模式关闭外部文件访问。

</DocCard>
  <DocCard title="数据本身" index="05">

静态包默认可被下载，不得放入密钥、令牌或私密数据。

</DocCard>
  <DocCard title="发布版本" index="06">

缓存键包含发布版本身份；换版本即失效，避免新旧资源块混用。

</DocCard>
</CardGrid>

<Callout tone="amber" title="SHA-256 不等于可信发布者">
  SHA-256 只证明“内容与 Manifest 一致”，不证明“发布者可信”。后者要靠 Ed25519
  签名与信任固定。
</Callout>

</Module>

## 2. 三种部署形态

<Module>

<CardGrid columns={3}>
  <DocCard title="目录 + CDN" tag="推荐">

每个资源独立 HTTP Range；资源多、按需读取、可缓存。需要正确配置 Range 与 CORS。

</DocCard>
  <DocCard title="单文件 .wsql" tag="单对象">

整包下载，或流式只读头部再按文件 Range；适合原子替换与单对象发布。

</DocCard>
  <DocCard title="Node 本地目录" tag="构建期">

文件句柄加精确偏移，适合构建、测试与离线工具；需要包根 containment。

</DocCard>
</CardGrid>

三种形态对上层 API 完全一致，因为它们都实现同一个 `ResourceReader` 契约。

</Module>

## 3. 为什么还有一个 Rust crate

<Module>

<Callout tone="amber" title="对照基线，不是生产引擎">
  `crates/vector-benchmark` 是确定性精确 Cosine 基线，用于对照 TypeScript
  实现的正确性与性能，不进入运行时。它的存在是为了让“TS 算得对不对”有一个独立参照。
</Callout>

</Module>
